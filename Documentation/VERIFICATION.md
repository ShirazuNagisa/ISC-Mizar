# 验收清单

分三层。前两层可以在任何一台开发机上自动跑完；第三层需要真机。

## 一、逻辑层（不需要模拟器，秒级）

```bash
Scripts/test.sh          # MizarKit / MizarApp / MizarUI：142 条测试
```

覆盖：契约解析、HTTP 归一化、SPKI 提取（与 Go 的
`RawSubjectPublicKeyInfo` 逐字节对照）、配对码归一化、候选地址降级、
错误优先级、令牌存储、多服务端持久化。

### 占用口径（v0.2.1）

概览页的四张卡与资源页一样，CPU / 内存 / 网络 读的是 `footprint`
（**那台服务器上这套东西自己**的占用：内核 + 站点进程树），而 GPU 只能
是设备级的，因此值下面写明"整机"。

契约测试守着三件事，它们的共同点是"错了之后症状与原因隔得很远"：

- **网络的三态可分**：`darwin-nettop` / `unsupported` / `unavailable`。
  速率字段在两种不可用的情况下**缺省**。若用一个非可选的 0 表示，
  "没有进程级采样"和"现在不占网络"就分不开了，界面只能猜 ——
  而猜错的那一半会让用户得出相反的结论。
- **旧内核仍可解析**：0.4.0 之前的内核不发 `footprint`，老服务器不能让
  升级后的手机端看到空白页。
- **CPU 可以超过 100%**：多核机器上它是各进程之和（每个进程的 100% 指
  "一个核跑满"），进度条前必须钳到 0...1。

## 二、真链路（模拟器 + 真实内核）

```bash
# 在 ISC-Core 里
CGO_ENABLED=0 go build -o /tmp/isc-acc/isc ./cmd/isc
# 回到这里
Scripts/acceptance.sh        # macOS 上的 MizarKit（不需要模拟器）
Scripts/acceptance-ios.sh    # iOS 模拟器上的真实应用 + watchOS 模拟器上的手表应用
Scripts/build-ios.sh         # 只构建
Scripts/build-watch.sh       # 只构建（watchOS）
```

`acceptance-ios.sh` 是唯一能回答 **iOS 的 ATS 会不会挡住自签证书** 的检查。
结论是不会（见 `PRODUCT-ARCHITECTURE.md`）。

### Phecda 的「远程访问」页

已在一台真实机器上目视确认（截图见 `ISC-Phecda/Documentation/images/remote-page.png`）：
开关、监听端口、状态（正在监听）、公钥指纹、证书有效期、已配对设备数、
全部候选地址（IPv4 + 六条 IPv6 + `.local` 主机名，各带复制按钮）、
以及配对入口。

指纹在界面与 `isc remote status` 两条路径上一致 —— "手机上显示的那串
和这里的一样吗"是用户核对中间人攻击的唯一手段，因此它必须一致。

## 三、真机（必须人工，因为模拟器没有对应硬件）

| # | 检查 | 为什么模拟器做不了 |
|---|---|---|
| 1 | 相机扫码配对 | 模拟器没有摄像头 |
| 2 | 手输六位码 + 指纹核对弹窗 | 可以自动化，但要有人确认文案读得懂 |
| 3 | 切 WiFi / 关 WiFi / 开蜂窝后的自动重连 | 模拟器共享宿主网络，不会真的断 |
| 4 | 应用切后台再回前台 | 模拟器的挂起行为与真机不同 |
| 5 | 锁屏状态下收到通知 | 需要付费开发者账号 + 真机；内核侧的发送链路已用假 APNs 覆盖（48/48 中的推送那一节） |
| 6 | Apple Watch 上看到同一台服务端 | 需要在**同一对**真机上装两个应用（模拟器上的手表与手机不是配对的） |
| 7 | 长时间挂着（电池与发热） | 模拟器不吃电池 |
| 8 | 服务端地址变化（换网段）后能否自愈 | 需要真的改网络 |

前四项在任何一台 iPhone 上十分钟能跑完，而它们是"这个应用到底能不能用"
的全部判据 —— 其余的是锦上添花。
